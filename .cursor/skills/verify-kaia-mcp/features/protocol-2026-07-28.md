# Protocol 2026-07-28 (SDK v2)

The HTTP endpoint speaks MCP protocol revision **2026-07-28** through SDK v2 `createMcpHandler`, while still serving 2025-era clients via the stateless legacy fallback. Modern clients probe with `server/discover`, send the per-request `_meta` envelope, and set `MCP-Protocol-Version` / `Mcp-Method` / `Mcp-Name`. A header that disagrees with the body is refused with JSON-RPC `-32020` (HeaderMismatch). `tools/list` results carry `cacheScope: "private"` because the list is filtered by the token's scopes.

## Sub-features

- `protocol-version` accepts `MCP-Protocol-Version: 2026-07-28` on a modern `server/discover`.
- `server-discover` answers `server/discover` with `supportedVersions` containing `2026-07-28`, no `Mcp-Session-Id`, and no prior `initialize`.
- `header-mismatch` answers a modern request whose `Mcp-Method` disagrees with the body (or is absent) with HTTP 400 and JSON-RPC `-32020`.
- `cache-scope-private` answers a modern `tools/list` with `cacheScope: "private"` and `ttlMs: 0`, listing only tools the token may call.
- `legacy-fallback` still answers a 2025-era `initialize` with `serverInfo` and no session.
- `rejection-log-hygiene` logs an SDK rejection as one `level=info msg=MCP request rejected code=<code> cell=<cell>` line: a crafted `params.name`, `Mcp-Name` or `_meta` protocol version never reaches the log (no new `outcome=allowed` or `msg=Tool call tool=generate_wallet ` line), and a 1 MiB name adds a few hundred bytes, not a megabyte.

## How to get to it (user POV)

- Get a `kaia:encode` token through the device flow (so `tools/list` is a non-empty, scope-filtered list).
- `POST /` `server/discover` with the modern `_meta` envelope and matching `MCP-Protocol-Version` / `Mcp-Method` headers.
- `POST /` the same body with `Mcp-Method: tools/list` (mismatch) and again with no `Mcp-Method`.
- `POST /` modern `tools/list` with matching headers.
- `POST /` legacy `initialize` with `protocolVersion: 2025-11-25` and no modern headers.
- With a `kaia:read` token, `POST /` modern `tools/call` whose `params.name` is `x msg=Tool call tool=generate_wallet outcome=allowed tokenFingerprint=000000000000` (with `Mcp-Name: x`); again with that text in the `Mcp-Name` header; again with it as both the `_meta` protocol version and the `MCP-Protocol-Version` header; then three calls with a 1 MiB name.

## Gotchas

- A request without the `_meta` envelope and without a `MCP-Protocol-Version: 2026-07-28` header is classified as legacy and does not exercise `-32020`. With that header but no envelope it is not legacy: it is refused with HTTP 400 and `-32602`.
- On the modern path the SDK's own rejection text quotes the caller's name and header values. Count `outcome=allowed` across the whole log, not per tool, and expect the rejection line to carry only `code`, `cell`, `errorType` and the token fingerprint.
- `cacheScope` must stay `"private"` for `tools/list`: the list varies by token. Do not treat a public cache as safe.
- Older clients that never send `MCP-Protocol-Version: 2026-07-28` still work through the legacy initialize path.
